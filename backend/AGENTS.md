# Правила репозитория

## Стек
Бэкенд: Python 3.12, FastAPI, синхронный SQLAlchemy 2.0, SQLite, APScheduler, httpx, pydantic v2.
LLM: OpenRouter (OpenAI-совместимый API), модель из LLM_MODEL (по умолчанию DeepSeek). Только извлечение, публикует человек.
Фронт (frontend/): React 18 + TypeScript + Vite, без UI-библиотек и роутеров.
Выкат: общий Dockerfile в корне (фронт + бэкенд в одном образе), Caddy — только HTTPS на сервере. См. DEPLOY.md. Один процесс бэкенда, один воркер.
Не добавлять: Celery, Redis, Alembic, ORM-обёртки, DI-фреймворки.

## Код
- Простой прямолинейный код. Одна функция — одно дело. Абстракции только там, где явно указано.
- Типизация обязательна.
- Время — UTC, timezone-aware.
- Никаких print, только logging.
- Секреты только из .env.

## Данные
- Из профиля MAX сохраняем ТОЛЬКО user.id. Имя, фамилию, username, фото, ip — не сохраняем нигде.
- Списковые поля в SQLite хранятся как ",a,b," и фильтруются через LIKE '%,code,%'.
- У каждого опубликованного события обязаны быть source_url и verified_at.

## Продуктовые запреты
- Не вычислять и не выводить льготы при поступлении. Только текст организатора + ссылка.
- Не публиковать событие автоматически: только через одобрение человеком.
- Не собирать телефон, ФИО и школу.

## Тесты
Обязательны три файла: подпись MAX, фильтры каталога, сквозной сценарий. Внешние API мокаются.
