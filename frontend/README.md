# Дерзай — frontend MVP агрегатора возможностей

React 19 + TypeScript + Vite. Только frontend, без backend, авторизации и подачи заявок.

## Запуск

Нужен Node.js 20.19+ или 22.12+.

```sh
cd frontend
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. Если архив распакован непосредственно в `frontend`, выполняйте команды в этой папке без дополнительного `cd`.

```sh
npm run build
npm run typecheck
npm run lint
npm test
npx playwright install chromium
npm run test:e2e
```


## Сценарии

Пять экранов онбординга; возврат не теряет ответы. Профиль и завершение сохраняются в localStorage. Повреждённое или недоступное хранилище обрабатывается. На экране профиля можно изменить ответы или пройти онбординг заново.

Лента предзаполняется классом, допуском участников из региона и предпочтительными типами. Цели каталога независимы от свободного текста. Общие и специальные фильтры работают по AND между полями / OR внутри поля. Выбор одного типа показывает его дополнительные поля, смена типа очищает несовместимые ограничения. В bottom sheet изменения — черновик до «Применить»; закрытие отменяет их. «Сбросить» очищает черновик, профиль не удаляется. «По моему профилю» восстанавливает персональные ограничения.

Даты проведения фильтруются по пересечению периодов. Диапазоны чисел включают границы. Булевы поля имеют три состояния: без ограничения / да / нет; неизвестные данные не равны «нет». Онлайн не означает допуск из любого региона. «Дедлайн скоро» — приём открыт, до окончания 0–7 дней включительно.

## Демо и сервис

Все 16 мероприятий вымышлены (4 каждого типа), условия и даты не являются реальными предложениями. Единая дата демонстрации: **24 сентября 2026** (`clock.today()` в `src/services/opportunities.ts`). Поэтому демо воспроизводимо независимо от даты запуска. События без настоящей ссылки не имеют кнопки подачи заявки.

Под лентой раскройте «Демонстрационный режим», чтобы включить медленную загрузку (5 секунд), ошибку или пустую выдачу. «Повторить попытку» после демонстрационной ошибки возвращает обычный сервис. Сброс пустой выдачи возвращает все демособытия.

## Структура

- `src/pages/` — онбординг и подробности.
- `src/App.tsx` — навигация, лента, профиль и композиция состояния.
- `src/components/` — UI и модальная панель фильтров.
- `src/state/` — фильтрация, валидация и хранение профиля.
- `src/types.ts` — общая модель и discriminated union четырёх типов.
- `src/data/` — справочники и демособытия.
- `src/services/` — асинхронный контракт данных, AbortSignal, единые часы.
- `src/integration/max.ts` — граница будущей интеграции MAX, сейчас браузерный режим.
- `src/styles.css` — токены и адаптивные стили.
- `tests/domain.test.ts` — правила фильтрации и сохранение профиля.
- `tests/e2e/journey.spec.ts` — основной путь на 320/375/390/430 px.

## Макеты и ограничения

Изучен PDF «кластеризация.pdf». Через браузер просмотрены отдельно пять фреймов онбординга и секция состояний Figma. Онбординг визуально приближен к ним; точное воспроизведение не заявляется: MCP исчерпал лимит, оригинальные иконки/логотип и параметры шрифта не удалось получить. Использованы системный шрифт, CSS-градиент и временные знаки-иконки. Исходный `public/assets/texture.png` сохранён, но не используется. Верхние X/меню макета трактуются как оболочка MAX и не дублируются; это требует проверки в клиенте MAX. Кнопка «назад» внутри анкеты отвечает только за шаги.

Лента, цели, фильтры, подробности и профиль спроектированы самостоятельно в близком визуальном языке. Упоминание календаря и уведомлений в приветствии макета заменено, поскольку эти функции исключены заданием.

Production build, TypeScript, ESLint и 14 unit-тестов проверены. Через встроенный браузер выполнены основной путь и визуальная проверка. Подробности фактических проверок и ограничения запуска Playwright см. `VERIFICATION.md`.
